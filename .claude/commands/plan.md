Read the requirement, project instructions, effective configuration and actual affected code. Use the architect role in `roles/architect.md`. Verify named files, symbols and API signatures before referencing them.

For significant work write `plan.md` using `templates/plan-template.md`: approach, affected projects/contracts, dependency ordering, relevant risks and verification. For simple changes record the short approach with the checklist. Follow project architecture and command conventions. Respect plan-only requests and configured gates; do not impose a universal language or branch workflow.
