# pi (pi.dev) setup — the powerful build

pi ships only 4 built-in tools (`read`, `write`, `edit`, `bash`); everything else comes from
**packages** declared in `settings.json`. This kit wires pi up to near-parity with Claude Code:
MCP, subagents, a plan-mode guardrail, and background jobs.

## What `setup.sh pi` installs

| File / package | Goes to | Purpose |
|---|---|---|
| `models.json` | `~/.pi/agent/models.json` | GLM-5.1 + Qwen3-Coder-Next over your `/v1` endpoint |
| `settings.json` | `~/.pi/agent/settings.json` | the `packages[]` load list (below) |
| `mcp.json` | `~/.pi/agent/mcp.json` | MCP servers (read by pi-mcp-adapter) |
| `subagent-config.json` | `~/.pi/agent/extensions/subagent/config.json` | per-agent model overrides for pi-subagents |
| `SYSTEM.md` | `~/.pi/agent/APPEND_SYSTEM.md` | terse rule spine appended to the system prompt |
| `agents/*.md` | `~/.pi/agent/agents/` | the enabled subagents (per `config/pipeline.yaml`), generated by `port-agents.py` |

**Default packages** (`settings.json`):

| Package | Role | Why |
|---|---|---|
| **`pi-mcp-adapter`** | MCP bridge | One ~200-token `mcp()` proxy instead of per-tool schema bloat; lazy spawn; disk cache; `directTools` promotion. Reads our `mcp.json`. |
| **`pi-subagents`** | subagents | `/run`, `/chain`, `/parallel`, JSON-schema gates; runs our ported `planner/tech-designer/engineer/qa-lead/go-code-reviewer/devops-lead` (+ the `rlm` utility), whichever are enabled in `config/pipeline.yaml`. |
| **`@pi-vault/pi-plan`** | read-only plan mode | Blocks `edit`/`write` + allowlists read-only `bash` during planning — enforces "no mutation before `tasks.md` is approved" (phases 3–4). |
| **`pi-patty-bg-tasks`** | background jobs | `task test`/`task lint`/migrations auto-background after ~15s; `/bg-list` manager keeps the agent unblocked at the DoD gate. |

## Quickstart

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
./setup.sh pi                                  # from the kit root; installs the packages above
set -a; source .env; set +a
pi --model selfhosted/Qwen3-Coder-Next         # or selfhosted/GLM-5.1
```

## Command cheat-sheet

| Need | Command |
|---|---|
| MCP server status / tools | `/mcp`, `/mcp tools`, `/mcp reconnect [server]` |
| Call an MCP tool (proxy) | the model calls `mcp({tool:"find_symbol", args:"{...}"})` — `args` is a JSON **string** |
| Run a specialist agent | `/run planner "spec PROJ-1234"` |
| Chain the pipeline | `/chain planner "spec PROJ-1234" -> tech-designer "plan it" -> engineer "implement"` |
| Read-only plan mode | `/plan` (or `pi --plan`); `/plan off` to restore tools |
| Background a long job | auto after ~15s, or `Ctrl+Shift+B`; manage with `/bg-list` |

## The subagents are generated (single source — don't hand-edit)

`agents/*.md` here are **generated from `.claude/agents/*.md`** by `port-agents.py` (pi-subagents uses
`.pi/agents/`/`~/.pi/agent/agents/`, not `.claude/agents/`, and pi-specific frontmatter keys). Edit the
canonical agents under `.claude/agents/`, then regenerate:

```bash
python3 agents-config/pi/port-agents.py            # → agents-config/pi/agents/
python3 agents-config/pi/port-agents.py ~/.pi/agent/agents   # straight into pi
```
The porter remaps `tools` (Read→read, Glob→find, `mcp__atlassian`→`mcp:atlassian`), `model`
(opus→GLM-5.1, sonnet→Qwen3-Coder-Next), and adds `systemPromptMode: append`,
`inheritProjectContext: true`, `completionGuard: false` (all but `engineer`).

## MCP

pi has no native MCP, so the kit uses **`pi-mcp-adapter`** (in `packages[]`): one ~200-token `mcp()`
proxy instead of per-tool schema bloat, lazy spawn, disk cache, and `directTools` promotion. It reads
`mcp.json` (copied to `~/.pi/agent/mcp.json` by setup) — no `/mcp setup` step needed.

## Optional add-ons (not in the default set)

```bash
pi install npm:@geminixiang/pi-diff@0.0.4              # /diff — browser diff viewer for review (phase 7)
pi install npm:pi-web-access@0.10.7                    # web_search/fetch_content (needs EXA/GEMINI/PERPLEXITY key)
pi install npm:@juicesharp/rpiv-ask-user-question@1.20.0  # structured questions for the /clarify phase
pi install npm:@gotgenes/pi-permission-system@16.0.1     # approval gating (pi has no permission popups)
pi install npm:@hypabolic/pi-hypa@0.1.6                  # context-window compression (helps small-ctx models)
```

**Deliberately not used:** `pi-lens` (overlaps Serena + `gofumpt`/format-and-guard — would fight the
formatter), memory packages (`pi-hermes-memory` etc. — we commit `.serena/memories/` per repo),
`rpiv-todo` (our version-controlled `tasks.md` is the todo list).

## Versions (verified against the npm registry, 2026-06-24)
Default set, pinned in `settings.json`: `pi-mcp-adapter@2.10.0`, `pi-subagents@0.31.0`,
`@pi-vault/pi-plan@0.1.0`, `pi-patty-bg-tasks@0.2.0`. pi CLI: `@earendil-works/pi-coding-agent@0.80.2`.
All four declare `"pi": {"extensions": [...]}`, so listing them in `packages[]` loads them — no init
step. **`@pi-vault/pi-plan` requires Node ≥ 24.15.0** (the others don't pin an engine); if `/plan`
errors, upgrade Node. Bump these as a `chore(deps)` commit when you update.

## Verify after install
`/mcp` (servers up), `/mcp tools` (Serena `directTools` present), `/run planner "spec PROJ-0000"`
(subagents work). Verify the exact pi builtin tool names with `pi`/`/tools` (the porter assumes
`read/write/edit/bash/grep/find`).
