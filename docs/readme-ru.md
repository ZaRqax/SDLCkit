# SDLCkit 2.0

Кит помогает Codex, Claude Code, OpenCode и Cursor работать с существующими проектами: принять требование из сообщения, файла или подключённой системы, выбрать подходящий процесс, внести изменение, проверить результат и подготовить нужный артефакт.

Сам кит может находиться в `~/tools/SDLCkit`, а репозитории — в другом каталоге. Перемещать их не нужно. Язык, архитектура, команды тестов и правила веток берутся из проекта. Jira, Confluence, GitHub, GitLab, Serena, MCP и локальные модели подключаются только по необходимости.

```bash
./setup.sh --target /workspace/projects --harness codex --dry-run
./setup.sh --target /workspace/projects --harness codex --non-interactive
./setup.sh --target /workspace/projects --doctor
```

Сначала просмотрите создаваемые файлы и конфликты. Установщик сохраняет существующие инструкции и настройки, ведёт манифест владения и поддерживает удаление без потери пользовательских правок. Готовый промпт для настройки агентом находится в [onboarding.md](onboarding.md); используется тот же механизм установки.

Небольшая правка требует краткого описания и целевых проверок. Значительная функция получает план, задачи и ревью. Для нескольких репозиториев строится граф зависимостей, а каждый пишущий агент работает в отдельном git worktree. Расследование заканчивается отчётом без изменений продукта. Обязательной церемонии из восьми фаз нет; действуют реальные правила проекта и разрешённый объём работы.

Результат выбирается отдельно: отчёт, рабочее дерево, patch, локальный коммит/ветка, явно разрешённый PR или MR. Запрос локального patch не разрешает push, комментарии или переходы тикетов. Проверки фиксируют настоящие коды завершения; недоступная команда не считается успешно пройденной. Автоматические merge, production deploy, раскрытие секретов и разрушительные операции запрещены.

Оркестратор и наблюдатели запускаются только явно. Они сохраняют состояние, события, попытки, зависимости и результаты. Старые команды установки pi/Qwen/Crush/omp, портеры и полезные Go-навыки сохранены; Go-конвенции теперь являются [опциональным профилем](../profiles/go/).
